## Installer candidate

The saved-options and Dock fixes were qualified on Tahoe candidate `5d70802e66eee3f737207bb77ff3b046d354035e` for v0.85.12. The earlier shell preflight candidate was `cb89f3f92bb05bef3f569f2cc573021f3578b5f1`, based on v0.85.8. This check runs before installation changes the desktop. The installer also detects when a package transaction replaces the running KWin executable and asks the user to restart the session before applying the desktop.

The neon 6.7.5 repair required the matching native libplasma packages. The APT simulation identified one optional test fixture, plasma-sdk, for removal. After removing that fixture in the guest, APT installed the signed packages with removals disabled. Both the shell and compositor reported 6.7.5 in the graphical session after reboot. The ordinary installer preserved the prepared guest's existing Dock setting. A fresh-layout probe expected a different setting. With explicit layout selection, the same guest then passed the dark and light pixel checks, reboot and uninstall.

The candidate includes the dual-backend Ninja correction, safer APT and pacman transactions, preservation of user-owned color schemes on removal, layout restoration after reinstall and a VM-first warning in the installer. The Golden Gate installation instructions give that warning before the commands in all 15 README languages. A separate prepared neon 6.8.1 guest installed the exact candidate with explicit layout selection, passed the installed desktop probe, reinstalled using the ordinary settings, passed the probe again and uninstalled. Earlier matrix runs identify the base and patches used for each check.

## Arch dependency installation

When dependencies are missing on Arch-family systems, cli.py calls pkg_sync_install. The current mapping runs pacman -Sy and then pacman -S for selected packages. This can mix newly resolved libraries with an older installed desktop. The passing tests explicitly expect this sequence. First remove the standalone refresh from this installer path. Use the installed repository database, stop on transaction failure, and tell the user when a normal distro update and installer retry are needed. Leave system-wide upgrades under user control. Exercise a stale mirror, fresh database, failed transaction and already-satisfied dependencies in a disposable guest. Check the package transaction log and desktop state on each exit.

A local candidate against the pinned Tahoe commit removes the standalone pacman refresh and adds a recovery hint after a failed transaction. The candidate passed all 443 tests in test_distro_packages.py and test_utils_deps.py. The new cases exercise the production Arch command mapping and simulate transaction failure. A separate native transaction check used pacman 7.1.0 and libalpm 16.0.1 in an isolated mount, user and network namespace with a disposable package root. The candidate called the real pacman against a local repository containing two unsigned fixture packages. A missing archive caused a failed download with zero packages installed. An existing database lock stopped the transaction and remained in place. After restoring the archive and releasing the test lock, retry installed the dependency exactly once. A second request skipped it. The sync database and a previously installed file retained their SHA-256 hashes. The transaction log showed one database sync during fixture setup and none by the candidate. Candidate patch SHA-256 was `a5d041dcac3dd352fc66c755887d67ac352c67d3fda10176ef118a2aa55ffc60`. The rolling Arch, Artix and CachyOS desktop runs below subsequently exercised the ordinary dependency path with their distro repositories.

## Execution order

1. Inventory released guest images and archived **coherent distro snapshots** for each cell below. Record distro release, repository snapshot, Plasma, KWin, KWin development package, Qt, session backend and source commit. Keep rolling and unstable jobs identified by their measured versions. Mark unavailable cells with the missing snapshot, SDK or session package.
2. For each available cell, resolve the full requested dependency set and run the native transaction in an isolated guest. Check package ownership, architecture, already-installed packages and missing providers. Exercise a locked manager, offline mirror and insufficient space. Verify failures stop subsequent install steps and a retry recovers. For NixOS, use its documented declarative configuration and rollback path.
3. Compile the shipped native components against the guest SDK, install them, restart the session, inspect plugin load errors and capture a rendered effect with its setting off and on. Exercise Wayland and X11 wherever shipped. Record each backend separately. At the 6.6→6.7 and 6.7→6.8 transitions, upgrade a working guest and verify stale plugins are replaced or disabled safely before reuse.
4. Start with an existing customized user profile and record its baseline. Run the ordinary installer, reinstall, interrupt and retry, reboot, and uninstall. Check KWin and Plasma start, the chosen edition defaults apply, pre-existing settings and unrelated files survive, and package or build failures never produce a successful completion message. Exercise Tahoe and the staged Golden Gate entry point. Associate shared evidence with its exact staged source fingerprint.
5. For each run, record build, module load, visible result, lifecycle and recovery separately, with logs/captures and source hashes. Fix reproduced defects and rerun affected cells. Report unavailable combinations and failures explicitly before changing compatibility claims.
